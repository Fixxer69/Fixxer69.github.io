# BioLab Hub: сайт для команды

Сайт с настоящими аккаунтами: вход по паролю, одобрение заявок администратором,
общая база химикатов и буферов, документы (PDF) и календарь бронирования.
Все данные хранятся в JSON-файлах в папке `data/`, а записывает их только скрипт `app.py`.

```
app.py             сервер (Python, Flask)
requirements.txt   нужные пакеты
public/            страницы сайта: index.html, calendar.html, style.css
pdf/               ваши PDF (видны только вошедшим и одобренным участникам)
seed/              стартовые данные (химикаты и буферы), копируются в data/ при первом запуске
data/              создаётся сам: пользователи, брони, данные. Его нельзя публиковать
```

## 1. Запуск на своём компьютере

```
python -m venv .venv
.venv\Scripts\activate          (Windows)   или   source .venv/bin/activate   (Mac/Linux)
pip install -r requirements.txt
python app.py create-admin      (придумайте логин и пароль администратора)
python app.py
```
Откройте http://127.0.0.1:8000 и войдите как администратор.

## 2. Публикация на PythonAnywhere (бесплатный план подходит)

Интерфейс сайта иногда меняется, названия кнопок могут немного отличаться.

1. Зарегистрируйтесь на pythonanywhere.com (аккаунт «Beginner», бесплатно).
2. Вкладка **Files**: создайте папку `biolab` и загрузите в неё все файлы проекта
   (удобнее загрузить `biolab-team.zip` и распаковать в консоли: `unzip biolab-team.zip`).
3. Вкладка **Consoles**, «Bash»: выполните
   `cd ~/biolab` и `python3 app.py create-admin`.
4. Вкладка **Web**, «Add a new web app», «Manual configuration», версия Python 3.10 или новее.
5. На вкладке Web откройте **WSGI configuration file** и замените всё содержимое на:
   ```python
   import os, sys
   path = '/home/ВАШ_ЛОГИН/biolab'
   if path not in sys.path:
       sys.path.insert(0, path)
   os.environ['LAB_TZ'] = 'Europe/Berlin'      # часовой пояс лаборатории
   from app import app as application
   ```
6. На вкладке Web включите **Force HTTPS** и нажмите зелёную кнопку **Reload**.
7. Откройте `https://ВАШ_ЛОГИН.pythonanywhere.com`.

Бесплатное приложение нужно раз в несколько месяцев подтверждать кнопкой на вкладке Web.
На своём сервере (VPS) запускайте так: `gunicorn -w 2 -b 127.0.0.1:8000 app:app` за nginx с HTTPS.

## 3. Настройки (переменные окружения)

| Переменная | Что делает |
|---|---|
| `LAB_TZ` | часовой пояс для проверки «прошедших» броней, например `Europe/Berlin` (по умолчанию UTC) |
| `DATA_DIR` | куда писать данные (по умолчанию `data/` рядом с `app.py`) |
| `COOKIE_SECURE=1` | помечать cookie входа как «только по HTTPS» (включается само, если соединение HTTPS) |
| `PORT`, `HOST` | порт и адрес при запуске `python app.py` |

## 4. Как всё работает

* Новый человек нажимает «Create account». Он получает статус «ожидает», пока администратор не нажмёт «Approve» в админ-панели (вкладка Members).
* Администратор может сделать другого человека администратором, отозвать доступ или отклонить заявку.
* Участники читают базу, документы и календарь и бронируют сами. Менять базу и документы могут только администраторы.
* Бронь Room A задаётся временем «с и до» (08:00–22:00, шаг 30 минут). Пересечения проверяет сервер, поэтому занятое время не занять даже двумя одновременными кликами.
* Документы: ссылка Google Drive (файл открыт «Anyone with the link can view») или PDF из папки `pdf/` (вписывается как `pdf/название.pdf`).

## 5. Резервные копии и пароли

* Копируйте папку `data/` (например, раз в неделю). Рядом с каждым файлом лежит `.bak` с предыдущей версией.
* Забыли пароль администратора: `python app.py create-admin`, введите тот же логин, и пароль заменится.

## 6. Что сделано для безопасности

* Пароли хранятся только в виде хеша (scrypt), сессии лежат на сервере, cookie входа `HttpOnly` и `SameSite=Lax`.
* Все права проверяет сервер: кто может читать, бронировать, менять базу, одобрять заявки.
* Защита от подделки запросов (CSRF), ограничение попыток входа (8 за 10 минут), ограничение регистраций.
* Все данные проверяются и обрезаются на сервере. Ссылки допускаются только `https://` и пути вида `pdf/…`.
* Запись файлов атомарная и под блокировкой: файл не бывает записан наполовину.
* Папки `data/`, `seed/` и сам `app.py` не отдаются через сайт. PDF отдаются только вошедшим участникам.
* Заголовки безопасности (CSP, nosniff и др.).

Ограничения: JSON-файлы подходят для небольшой команды (десятки человек). Если станет больше, замените хранилище на SQLite или PostgreSQL. Письма для сброса пароля не отправляются, пароль сбрасывает администратор через команду выше.
